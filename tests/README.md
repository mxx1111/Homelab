# tests

前端渲染的回归测试。零 npm 依赖，用 node 内置能力跑。

## 跑法

先起一个面板（demo 模式最省事，不碰真机数据）：

```bash
HOMELAB_CONFIG=config.demo.yaml python run.py
```

另开一个终端：

```bash
node tests/nodeview.test.mjs http://127.0.0.1:8770
```

## 为什么不用 jsdom

前端零 npm 依赖是这个项目的一条底线。渲染函数返回的都是 HTML 字符串，
真正需要的只是让 `app.js` 顶层那些 `$("x").onclick = ...` 不炸——
`dom-stub.mjs` 做到这个程度就够，没必要为跑测试装几十 MB 的依赖。

## 守的是什么

`nodeview.test.mjs` 盯的是多节点重构里最容易回退的那条不变式：

**本机和每个节点必须渲染出同样多的卡位。**

重构前本机 13 张卡、节点 5 张粗卡加一段散文，切过去大半是空的。现在缺的模块
出统一占位而不是少一张卡，这条一旦回退，多节点的体验就退回原样了，
而这种回退在页面上不显眼——少两张卡没人会立刻发现。

顺带覆盖：模块数据缺失时的容错、卡片按状态排序且轮询时不抖动、
fleet 条的离线显示、告警条锚点映射。

`split.test.mjs` 盯的是前端拆成四个文件之后的新风险：**拼接起来能跑，不等于
浏览器里能跑**。浏览器按 `index.html` 的顺序逐个执行 script，任何一个文件在
顶层用到后面文件的东西都会当场报错；而 `nodeview.test.mjs` 是把四个文件拼成
一整段跑的，函数声明整体提升，发现不了这个。所以它单独检查引入顺序、
顶层执行语句的位置、以及有没有把同一段代码抄进两个文件。

这个不需要起面板：

```bash
node tests/split.test.mjs
```
